Wireframe: tutorial page on a 4K / 8K TV

The target layout for showing the tutorial on a large 16:9 TV in a classroom. Each frame below is a true scaled-down screen: inside a frame, 1% of the frame width equals 1% of the TV width. The page works like a slide show, with one screen per step, so nobody has to scroll a long page from across the room. The current layout is in design/wireframe.html.

Notes

  1. Step barAlways visible, about 3% of the screen height. Numbered chips jump straight to a screen. The key hints on the right change with the screen.
  2. Title screenThe intro from the current page, made big: the H1 is 4.4% of the screen width. The hero view sits on the right. There is nothing to scroll.
  3. Step title bandNumber, title, stack and file name on one line. The goal sentence moves up here, so it never wraps under the code.
  4. Code panel (54% of the width)Shows about 26 lines. Most steps are longer (Steps 4 and 5 have 67 and 70 lines), so the panel scrolls the active layer's lines to the middle by itself. Lines wider than the panel wrap with a hanging indent. A remote cannot scroll sideways, so nothing may need horizontal scrolling.
  5. View and layer stack (24%)The browser view sits on top, and the five layers fill the rest of the height. The active layer has a thick yellow outline that can be seen from the back of the room. L moves to the next layer, and its lines light up in the code.
  6. Notes column (22%)"What the code does", "Run it" and "Try it", stacked. They are always on screen, so the teacher can talk through them without switching.
  7. Code zoomThe code fills the screen at a larger size, about 18 lines. The layer list stays on the right, so L still works. Use it when the class needs to read the code itself.
  8. Compare screenAt TV width the matrix fits without its own scroll bar, so the current 820 px minimum width and sideways scrolling go away. The takeaways become one row of three cards.

Screen sizes

A TV browser does not always report its full pixel count. 4K and 8K panels often run the browser with scaling, so the page sees a smaller CSS viewport. That is why every size in this layout uses one unit, --u: min(1vw, 1.7778vh). It is 1% of the width on a 16:9 screen, and it shrinks to keep 16:9 when the window is taller or wider. The layout then looks the same on every row of this table.

Controls

→Next screen. PageDown and Space do the same, so a presenter clicker works. ←Previous screen. PageUp does the same. 0–6Jump to the title screen, a step, or the compare screen. LNext layer. Shift + L goes to the previous one. It lights up that layer's code lines. ZCode zoom on or off. EscClear the layer highlight.

What changes from the current page

  • The 1280 px max width is removed. The layout fills the whole 16:9 screen.
  • The long scroll becomes six screens. Each section is 100vh with scroll snap, so mouse scrolling still works.
  • All sizes use u, not fixed px.
  • Hover previews are dropped, because there is no hover from across a room. The keyboard drives the layers.
  • The browser mock is drawn in u, so its rectangles grow with the screen. The step files themselves are not changed.
  • Phones and laptops can keep today's scrolling layout below about 1600 px CSS width.
