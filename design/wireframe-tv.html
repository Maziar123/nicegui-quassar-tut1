Every step shows the same idea written for each column side by side, with one shared screenshot and cross-comments that link matching lines across the columns. Inside a frame, 1% of the frame width equals 1% of the TV width. The dashed orange line marks where one TV screen ends.

Notes

  1. Top barThe name and the column toggles. Any column can be hidden. With two columns showing, each code block gets half the width and long lines wrap less. Keys: 1 2 3 toggle a column.
  2. Left rail (14% wide)Summary, then each section with its steps. It stays in place while the page scrolls and marks the step you are reading. Click to jump.
  3. Summary: title and leadThe full name, "Quasar & NiceGUI & xxx: side-by-side cross-reference and tutorial", a short lead, and the target picture.
  4. Column legendOne colour per column, used everywhere: column headers, code tabs, chips and cross-comment refs. Blue for Quasar, green for NiceGUI, grey for xxx.
  5. Quick cross-reference tableThe cheat sheet: one row per idea, one cell per column, and a link to the step that teaches it. It is built from the cross-comments of all steps, so it never goes out of date.
  6. Section cardsEvery section with its step count. Click to jump.
  7. Step nameA number (section.step) and a short name. The section label sits above it.
  8. Step intro: comment left, one picture rightTwo or three short paragraphs about the idea. The picture is one image per step: a diagram, a sketch or the target result.
  9. Side by side: comment + code per columnEach column has a coloured header (name, file, line count), one or two lines of comment, then the code. Code lines that a cross-comment points to carry its number in a circle. If a column has nothing for a step, it shows a dashed "Not in xxx" box instead of code.
  10. Shared screenshotOne screenshot when all columns render the same page, with a chip per column and the pixel-diff result. When the results differ, it switches to one screenshot per column, lined up under the columns.
  11. Cross-commentsOne row per matching idea: a number, what matches, then a ref chip per column (line numbers and a short code hint). Select a row (hover, click or C) and its lines light up in every column at once. The other lines fade. This is the cross-reference at the heart of the page.
  12. Step footer"Run it" and "Try it", then links to the previous and next step.

How a step is stored

content/
  01-layout/
    section.toml          name, order
    02-two-boxes/
      step.toml           name, intro, picture, cross-comments
      picture.svg
      quasar.html         column 1 (runs on its own)
      nicegui.py          column 2 (runs on its own)
      xxx.*               column 3 (optional)
      shot.png            shared screenshot (made by the build)
  • Each code file still runs on its own, as the project rules require.
  • Cross-comments point at code with text markers, the same way find_range() works today. For example, nicegui = "ui.row()" finds the line. The build fails if a marker no longer matches.
  • The build makes the screenshots in headless Chromium, compares the columns, and writes the pixel-diff chip.
  • The quick cross-reference table on the summary is collected from every step.toml.

Sizing on 4K / 8K

  • All sizes use one unit, u = min(1vw, 1.7778vh). 4K and 8K look the same at any OS scaling.
  • With three columns, each code block is about 26 u wide. At 0.92 u code that fits about 45 characters, so longer lines wrap with a hanging indent. With two columns it is about 41 u, or about 70 characters.
  • Code is 0.92 u: 18 px on a 1920 px wide viewport, about 13 mm tall on a 65" TV. Body text is 1.05 to 1.25 u.
  • Below about 1600 px CSS width, the columns turn into tabs and the rail folds into a menu.
